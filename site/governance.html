TickerNet · project rules

Governance

TickerNet exists because the scheduler it came from moved from an open-source license to a commercial one. These rules make sure TickerNet itself can never take that step, while leaving everyone free to build what they like on top of it. The source of truth is GOVERNANCE.md and TRADEMARKS.md in the repository.

Build anything on itDerivatives welcome, proprietary ones too

Use, change and redistribute TickerNet under MIT or Apache-2.0, whichever you choose. Fork it, build closed-source or commercial products on it, and keep your changes private. Your freedom to build on it.

Open source, foreverTickerNet itself never goes commercial

Every TickerNet release stays MIT OR Apache-2.0: no paid edition, no source-available version, no license keys and no CLA. The irrevocable pledge.

Maintained and sponsored by

Omniscient AI set up the TickerNet fork, maintains it and funds its development, and makes these promises as the project's steward.

01

Sponsor and steward

Omniscient AI (Omniscient AI Private Limited) set up the TickerNet fork, maintains it and sponsors it. As steward it:

  • funds maintainer time and the project's running costs;
  • holds the project's name, the TickerNet GitHub organization, the docs site and the TickerNet package IDs on NuGet, on behalf of the project and its users, under the pledge below.

The steward does not own contributors' work. Contributors keep the copyright in what they write and license it to everyone under the project license, MIT OR Apache-2.0 (Contributing). ADR 0007 records the arrangement.

02

Your freedom to build on TickerNet

The project license is MIT OR Apache-2.0, at your option. Under either one you may:

  • use TickerNet in any product, open source or proprietary, free or paid;
  • fork it, change it and publish your own version under a different name;
  • build derivative works and license them on any terms the license you chose allows, including proprietary terms;
  • keep your changes to yourself.

What the license asks in return is small: keep the copyright and license notices (and, if you choose Apache-2.0, follow its notice and change-marking terms), and accept that the software comes without warranty. The pledge below is a promise TickerNet makes about itself. It adds no conditions to the license, and no future change to GOVERNANCE.md can take these freedoms away from code already released.

The only limit outside the license is the name: products built on TickerNet can't be published as "TickerNet". The name rules are below.

03

Open source, forever: the pledge

Made by Omniscient AI, as steward, and every maintainer, to TickerNet's users and contributors. It is irrevocable. Quoted from GOVERNANCE.md:

  1. Every release stays open source. Every version of TickerNet published from this repository, or under a TickerNet package ID on NuGet, is licensed under MIT OR Apache-2.0, with complete source code in this repository.
  2. No commercial edition under the TickerNet name. There will be no source-available, "community edition", paid-only, license-key, revenue-threshold or usage-limited version of TickerNet. Features will not be held back from the open-source release to sell them separately.
  3. No license changes by assignment. TickerNet does not use a contributor license agreement. Contributions are accepted under the project license with a Developer Certificate of Origin sign-off, so no single party collects the rights to relicense everyone's work.
  4. A handover keeps the pledge. If the steward stops supporting TickerNet, it will transfer the name, the GitHub organization, the docs site and the NuGet package IDs to an open-source foundation or to the active maintainers. It will not sell or transfer them to anyone who does not take on this pledge.

Paid services around TickerNet, such as support, consulting or hosting, are fine. They never change TickerNet's license or decide which features TickerNet gets.

The pledge and the freedoms above can be added to or made clearer, never weakened. ADR 0003 explains why TickerNet chose this license, this pledge and no CLA.

05

How decisions are made

  • Pull requests. Maintainers review and merge pull requests. A change goes in when a maintainer approves it and nobody with a good reason objects. Pull requests are merged with squash and merge.
  • Architecture decision records. Decisions that pick between real alternatives, add or remove a package or public interface, or set a rule other changes must follow get an ADR in the decision log.
  • Changing these rules. GOVERNANCE.md changes only through a pull request with an ADR. Changes may add to the pledge or make it clearer. They may never weaken it.
06

Security reports

Don't report security problems in a public issue. Use GitHub's private vulnerability reporting: open the repository's Security tab and choose Report a vulnerability (direct link). Say what the problem is, how to reproduce it, and what an attacker could do with it.

TickerNet is in preview, so security fixes go into the latest release only. SECURITY.md has the details.
