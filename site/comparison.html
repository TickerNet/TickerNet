TickerNet · coming from TickerQ

TickerNet and TickerQ compared

TickerNet started from TickerQ's last open-source code. TickerQ carried on under a commercial license from 10.5.0. This page sets the two side by side so you can choose, and links each gap in TickerNet to the issue that plans it.

How this page was written

  • TickerNet: version 1.1.0 and the main branch on 24 November 2026.
  • TickerQ: its public release notes for 10.5.0 to 10.5.2-rc.2 (October and November 2026). Under TickerNet's clean-room rule, nobody working on TickerNet reads TickerQ's code or documentation from 10.5.0 on, so this page describes TickerQ only as far as its release notes do. Check them for the current state.
Nothing from TickerQ 10.5.0 or later is in TickerNet. Where TickerNet adds a feature that TickerQ also has, it is designed from a description of the behaviour, never from TickerQ's code. Names and details may differ.

05

Roadmap

Every planned gap has an issue with the roadmap label. Reliability comes first, because it matters most in a job scheduler.

First: reliability

  • #47 Recover jobs left InProgress when a node dies, without Redis
  • #48 Wait for running jobs when the host shuts down
  • #49 Seed code-defined crons once, even when several hosts start together
  • #50 One-time startup jobs, created once per key
  • #51 Clean up old finished jobs and cron occurrences
  • #52 Skip pending runs when a cron ticker is disabled

Next: the managers and testing

  • #53 Get, list and delete by filter
  • #54 TickerResult.EnsureSuccess()
  • #55 Reschedule a job that hasn't started
  • #56 Cancel a function's pending jobs
  • #57 List a cron's next run times
  • #58 Wait for a job and read its result
  • #59 Schedule inside your EF Core transaction
  • #60 A replaceable clock for tests
  • #61 Application namespaces for environments that share a store

Later, or not planned

  • Later: longer and recurring chains, results passed from parent to child, a node list and search by ID in the dashboard, database tests against more EF Core providers, and a Native AOT publish test.
  • Not planned yet: business calendars and deployment fencing (ask for them in Discussions if you need them), .NET 8 and 9 (out of support), and a dashboard rewrite.
  • Not planned: an AI assistant in the dashboard. It would depend on an outside model provider and is not core to a scheduler.
