Write a new ADR

In the same pull request as the change it records.

  1. Decide whether it needs one. Write an ADR when a change picks between real alternatives, adds or removes a package or public interface, or sets a rule other changes must follow. Every change to GOVERNANCE.md needs one. Bug fixes and wording changes don't.
  2. Copy the template. Copy template.html to NNNN-short-slug.html, taking the next free number. Numbers are never reused.
  3. Fill it in. Keep Context to the problem and the forces at the time. Put concrete names (packages, types, settings, files) in Decision. List only alternatives that were really considered. Under Consequences, include the costs and any rule others must now follow. Every fact needs a source: a pull request, commit or file. Write "Not recorded" rather than invent a reason.
  4. Add it to this page. Add a row to the right area's table, update the counts at the top, and link the previous and next records' pagers.
  5. Don't rewrite history. To change an accepted decision, set its status to Amended and add a dated note to its status line, or write a new ADR that supersedes it, set the old one to Superseded, and link both ways.
  6. Keep them current. A change that alters, extends or contradicts an ADR, or moves a file one cites, updates that ADR in the same pull request.
