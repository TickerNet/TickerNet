ADR 0014 · Docs and process

Name the maintainers and a path to become one

GOVERNANCE.md now names TickerNet's one maintainer, says what protects users while there is only one, and sets out how contributors become triagers and maintainers.

Status
Accepted
Decided
2026-11-24
Affects
GOVERNANCE.md, site/governance.html

Related: ADR 0003 the license and pledge, ADR 0007 Omniscient AI sponsors TickerNet

01

Context

TickerNet has one maintainer. GOVERNANCE.md said "maintainers review and merge pull requests" without saying who they were or how anyone could become one. Before promoting the project, a review found that a single, unnamed maintainer is the first question users and critics ask of a company-sponsored fork, and that the required review on main is a formality while the only maintainer is also a repository admin.

02

Decision

  • A Maintainers section in GOVERNANCE.md and on the governance page names the maintainer, states plainly that one maintainer is a risk, and lists what protects users meanwhile: the license, the handover promise, and checks that don't rely on trusting one person.
  • A path: contributor, then triager (label, assign and close, no merge) after a few good contributions, then maintainer by invitation after about three months of steady contributions and reviews. A new maintainer accepts the pledge in the pull request that adds their name.
  • Maintainers inactive for six months become emeritus. Once there are two or more maintainers, every pull request needs approval from a maintainer who didn't write it.
  • The project states it is working towards a second person with owner access to the GitHub organization and the NuGet package IDs, and makes no promise it can't yet keep.
03

Alternatives considered

  • Say nothing until there is a second maintainer. Rejected: hiding the bus factor costs more trust when it is found than stating it does.
  • Add a second owner who doesn't maintain the code, and call them a maintainer. Rejected: it would overstate the review the code gets. A recovery-only owner is still planned, described as what it is.
04

Consequences

  • Adding or removing a maintainer is a pull request to GOVERNANCE.md, which needs an ADR only if it changes the rules, not for the names.
  • When a second maintainer joins, branch protection on main must stop letting admins bypass review, to match the rule above.
