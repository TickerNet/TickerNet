ADR 0010 · Code and packages

Accept TickerQ's names where moving would otherwise break

Where the rename would break something a user didn't write in code, TickerNet keeps the old TickerQ name working. Old dashboard links redirect, saved dashboard sign-ins carry over, TickerQ trace names are available on request, and TickerQ's remote-function names and column keep working. Names in code stay TickerNet.

Status

01

Context

ADR 0002 replaced TickerQ with TickerNet in every letter case. Besides the code, that changed names that live outside a user's code: the dashboard's default path, its browser storage keys, the ActivitySource, span and tag names, log text, logger categories, and the Redis InstanceName default and keyed-service key. Bookmarks, signed-in dashboard sessions and trace dashboards would break on upgrade.

Before the repository went public, the maintainer asked for backward compatibility wherever the old names could keep working. TickerQ is Arcenox LLC's name (TRADEMARKS.md), so TickerNet uses it only to describe compatibility, not as its own API.

02

Decision

  • Old dashboard links redirect, on by default. GET and HEAD requests to /tickerq/dashboard and anything under it, in any letter case, get a temporary redirect (302) to the same page under the configured base path. The rest of the path, the query string and the request's path base are kept. Other methods pass through. The redirect isn't added when the base path is /tickerq/dashboard or under it. DashboardOptionsBuilder.DisableTickerQPathRedirect() turns it off.
  • Saved sign-ins and time zone carry over. When the dashboard web app starts, before anything reads storage, it copies tickerq_basic_auth, tickerq_api_key, tickerq_host_access_key, tickerq_bearer_token and tickerq:dashboard:timezone to their tickernet names, in local and session storage separately. A value is copied only if the new key isn't set, and the old key is removed either way. Blocked storage is ignored.
  • TickerQ trace names, on request. AddTickerNetSource(useTickerQNames: true), an extension on TracerProviderBuilder in TickerNet.Instrumentation.OpenTelemetry, adds the TickerNet source and TickerQTraceNamesProcessor. When a span from that source ends, the processor renames its name and tag keys from tickernet.* to tickerq.*, so it must be added before any exporter. The instrumentation scope stays TickerNet. Off by default; AddTickerNetSource() alone is the same as AddSource("TickerNet").
  • TickerQ's remote-function names keep working. Jobs named function@node (RemoteFunctionName) and the IsSystemPaused column keep their meaning. SdkOfflineSkipException stays as an obsolete subclass of WorkerOfflineException, and the TickerFunctionProvider hooks stay. ADR 0009 covers these.
  • Not kept:
    • package IDs, namespaces, type and member names;
    • TQ0nn diagnostic IDs;
    • log message text and logger categories;
    • the dashboard's config script names, window.TickerQConfig, CORS policy name and OpenAPI tag;
    • worker thread names;
    • the Redis InstanceName default and the "tickerq" keyed-service key. Setting InstanceName = "tickerq:" keeps the old prefix.
    The migration guide lists each one with what to do.
03

Alternatives considered

  • Leave it to the migration guide. It already listed every changed name and how to keep the old value. Rejected by the maintainer, who asked for the old names to keep working where they can.
  • Shims with TickerQ's namespaces and API names, such as an obsolete AddTickerQ. Rejected: it would put TickerQ's name back into TickerNet's API, which ADR 0002 avoided, and code needs changing anyway for the new package references.
  • A permanent redirect (301 or 308). Rejected: browsers cache permanent redirects, so they would keep redirecting even after an app sets its base path back to /tickerq/dashboard.
  • Emit spans under both names. Not chosen: a span has one name, so only tags could be doubled, and that doubles the tag volume. Renaming at export, on request, keeps existing queries working without changing the default for new users.
04

Consequences

  • After an upgrade from TickerQ, stored data, dashboard links and dashboard sign-ins keep working with no change. Trace dashboards and alerts keep working with one opt-in call. Code still needs the rename.
  • A few public names contain TickerQ: DisableTickerQPathRedirect, TickerQTraceNamesProcessor, the useTickerQNames parameter and the obsolete SdkOfflineSkipException. They only describe compatibility, as TRADEMARKS.md allows.
  • Every app with the dashboard answers requests under /tickerq/dashboard with a redirect unless it turns that off.
  • Rule for later compatibility work: anything that changes what new users see is opt-in; redirects and carrying over old data may be on by default. Each item is listed in the migration guide and the README's backward-compatibility table.
