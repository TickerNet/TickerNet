ADR 0018 · Code and packages

Add TickerResult.EnsureSuccess() to rethrow failed results

TickerResult<T> gains EnsureSuccess(): it returns the result when the operation succeeded and rethrows the stored exception, with its original stack trace, when it failed.

Status
Accepted
Decided
2026-11-25
Affects
src/TickerNet.Utilities/Models/TickerResult.cs, tests/TickerNet.Tests/TickerResultTests.cs, site/getting-started.html

Related: ADR 0012 Target .NET 10 and .NET 11

01

Context

Every manager call returns a TickerResult<T>, and callers have to check IsSucceeded and Exception by hand. It is easy to forget, and then a failed schedule goes unnoticed. Issue #54 asks for a single call that either returns the result or throws the stored failure.

02

Decision

  • TickerResult<T>.EnsureSuccess() returns the same result instance when IsSucceeded is true, so calls can be chained.
  • When the operation failed, it rethrows the stored Exception with its original stack trace, via ExceptionDispatchInfo, instead of throwing a new exception.
  • The method has XML documentation and is covered by tests for the success and the failure path.
  • The getting-started guide shows EnsureSuccess() where scheduling is explained.
03

Alternatives considered

  • Returning the inner Result value instead of the TickerResult: rejected, because callers would lose AffectedRows and could not chain further checks on the result.
  • Throwing Exception directly: rejected, because a plain throw resets the stack trace to the rethrow point and hides where the failure happened.
04

Consequences

  • Callers can replace the hand-written IsSucceeded check with one call; a forgotten check no longer silently swallows a failed schedule.
  • The method is public API on TickerResult<T>, so it stays supported under the project license like the rest of the type.
  • New public API on this type follows the same shape: return the result on success, rethrow the stored exception on failure.
05
