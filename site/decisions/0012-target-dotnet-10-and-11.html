ADR 0012 · Code and packages

Target .NET 10 and .NET 11

From 1.1.0, every TickerNet package ships a net10.0 and a net11.0 build. Each build uses the Microsoft.Extensions and EF Core packages of its own .NET version.

Status
Accepted
Decided
2026-11-24
Affects
src/Directory.Build.props, samples/, benchmarks/, .github/workflows/

Supersedes the target framework part of ADR 0006 Version independently and target .NET 10 only. Related: ADR 0011 Publish packages from CI with NuGet trusted publishing

01

Context

ADR 0006 made TickerNet target net10.0 only. .NET 11 was released in November 2026 as a standard-term release; .NET 10 is the long-term release. Microsoft's release index gives both an end of support of 14 November 2028. Every TickerNet dependency that follows the .NET version, including EF Core and FlexLabs.EntityFrameworkCore.Upsert, has an 11.0.0 release. TickerNet 1.0.0 made Semantic Versioning binding on the public API (ADR 0006, amended), so dropping a target framework would need a new major version.

02

Decision

  • src/Directory.Build.props sets TargetFrameworks to net10.0;net11.0. DotNetVersion and DotNetAbstractionsVersion are [10.0.0,11.0.0) for net10.0 and [11.0.0,12.0.0) for net11.0, so each build depends on its own .NET version's packages.
  • The source generator stays on netstandard2.0, as Roslyn requires.
  • Tests run on both targets. Samples and benchmarks target net11.0 only.
  • CI and the release workflow install the .NET 11 SDK and the .NET 10 runtime.
  • Source Link comes from the .NET SDK; the Microsoft.SourceLink.GitHub package reference is removed.
  • Adding a target framework is a minor release (1.1.0). Dropping one is a major release.
03

Alternatives considered

  • .NET 11 only. Rejected: apps on .NET 10, the long-term release, could take no TickerNet update after 1.0.0, and it would be a breaking change needing 2.0.0.
  • Stay on .NET 10 only. Rejected: .NET 11 apps would run the .NET 10 build and pull in .NET 10 Microsoft packages beside their own.
  • One open version range such as [10.0.0,) for both. Rejected: a .NET 10 app could be moved onto EF Core 11 packages that don't support it.
04

Consequences

  • Contributors need the .NET 11 SDK, and the .NET 10 runtime to run the net10.0 tests.
  • Builds and test runs take about twice as long.
  • When .NET 12 ships, adding it follows the same pattern; dropping .NET 10 waits for a major version.
05

Where it lives

  • src/Directory.Build.props
  • src/TickerNet.SourceGenerator/TickerNet.SourceGenerator.csproj
  • samples/Directory.Build.props, benchmarks/Directory.Build.props
  • .github/workflows/ci.yaml, .github/workflows/release.yaml
