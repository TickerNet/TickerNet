ADR 0006 · Code and packages

Version independently and target .NET 10 only

TickerNet starts at 1.0.0-preview.1 with its own Semantic Versioning, and every package targets .NET 10 only, with no branches per .NET version.

Status
Accepted
Decided
2026-11-23
Affects
src/Directory.Build.props

Related: ADR 0005 Drop the TickerQ Hub integration

01

Context

Upstream used the .NET major version as its own major version: src/Directory.Build.props at the fork point has Version 10.4.0 and TargetFramework net10.0. It kept net8 and net9 branches in step with a sync workflow and the .sync-exclude and .sync-overrides lists, because some EF Core 10 APIs don't exist in EF Core 8 and 9. Commit 08b7fff removed the workflow and both lists.

02

Decision

  • Version 1.0.0-preview.1, set once in src/Directory.Build.props and shared by every package, following Semantic Versioning.
  • Target net10.0 only. Microsoft.Extensions and EF Core references are limited to [10.0.0,11.0.0).
  • No branches per .NET version.
03

Alternatives considered

  • Keep TickerQ's scheme (major version = .NET version). Rejected: it needs a branch per .NET version kept in sync, and version numbers would read like TickerQ releases.
04

Consequences

  • Users on .NET 8 or 9 stay on TickerQ's open-source 8.x and 9.x releases (those before 8.5.0 and 9.5.0) until TickerNet adds targets.
  • A TickerNet version number says nothing about TickerQ's.
  • One branch, main, and one build.
05

Where it lives

  • src/Directory.Build.props
