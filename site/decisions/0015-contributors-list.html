ADR 0015 · Docs and process

Credit contributors in CONTRIBUTORS.md

Everyone whose pull request is merged is listed by name in CONTRIBUTORS.md. The first step of the governance path, contributor, now says so.

Status
Accepted
Decided
2026-11-24
Affects
CONTRIBUTORS.md, GOVERNANCE.md, CONTRIBUTING.md, README.md, site/governance.html, site/contributing.html

Related: ADR 0003 the license and pledge, no CLA, ADR 0014 Name the maintainers and a path to become one

01

Context

The first outside contributor asked, on #24, to be named in a contributor list. TickerNet had none. Contributors were credited only by their commits, GitHub's contributor graph and the copyright line "the TickerNet contributors", and GOVERNANCE.md named only maintainers. With no CLA (ADR 0003), contributors keep their copyright, so naming them is also an honest record of who holds it.

02

Decision

  • A CONTRIBUTORS.md file at the repository root lists everyone whose pull request has been merged since the fork, by name and GitHub handle, in order of first contribution. It points to GOVERNANCE.md for the maintainers and to LICENSE and NOTICE for TickerQ's authors before the fork.
  • Contributors may add themselves in their pull request. If they don't, the maintainer who merges their first pull request adds them. Anyone can ask to be left off or listed differently.
  • A merged pull request is the bar. The list doesn't record what each person contributed; the git history does.
  • The contributor step in GOVERNANCE.md and on the governance page, CONTRIBUTING.md, the contributing page and the README link to the list.
03

Alternatives considered

  • Keep relying on the git history, GitHub's contributor graph and the "TickerNet contributors" copyright line, and offer triage access later as the credit that matters. Rejected: the contributor asked to be named, the graph shows handles rather than names, and it isn't part of the repository or linked from the docs.
04

Consequences

  • Merging a first-time contributor's pull request now includes checking they are on the list, and adding them if not.
  • Two open pull requests that both add a name to the end of the list conflict. The second one rebases, or the maintainer adds the name after merging.
  • Credit for issues, reviews and Discussions answers isn't recorded in the list. If that matters later, a new record can widen it.
05

Where it lives

  • CONTRIBUTORS.md
  • GOVERNANCE.md (Becoming a maintainer, step 1)
  • CONTRIBUTING.md (Pull requests)
  • README.md (Contributing)
  • site/governance.html (#maintainers)
  • site/contributing.html (#pull-requests)
