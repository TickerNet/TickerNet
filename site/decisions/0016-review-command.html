ADR 0016 · Docs and process

Re-request review with a /review comment

A pull request's author comments /review and a workflow asks everyone who reviewed it, and hasn't approved, to look again. @-mentioning the reviewer still works too.

Status
Accepted
Decided
2026-11-24
Affects
.github/workflows/review-request.yaml, CONTRIBUTING.md, site/contributing.html, AGENTS.md

Related: ADR 0014 Name the maintainers and a path to become one

01

Context

GitHub lets only people with the Triage role or higher request or re-request a review. Outside contributors don't have it, so after pushing fixes on #43 the author had to tag the reviewer in a comment instead. A pull request with changes requested then stays out of the reviewer's "review requested" list until someone with access re-requests it.

02

Decision

  • .github/workflows/review-request.yaml runs on issue_comment. When the pull request's own author comments /review on an open pull request, it re-requests review from every earlier reviewer whose latest review isn't an approval, and reacts to the comment. Bots, draft reviews and the author are skipped.
  • If nobody has reviewed yet, or everyone has approved, it says so in a comment. If GitHub refuses a request, it asks the author to @-mention the reviewer.
  • It has only pull-requests: write, uses the gh CLI on the runner, never checks out the pull request, and passes only the repository, number, author and comment ID to the shell, never the comment text.
  • CONTRIBUTING.md and the contributing page tell contributors to comment /review, or to @-mention the reviewer.
03

Alternatives considered

  • Give regular contributors the Triage role. Rejected: it helps only the people who have it, and it also lets them label, assign and close issues and pull requests, which ADR 0014 keeps for the triager step.
  • Only ask contributors to @-mention the reviewer. Kept as the fallback, but on its own it leaves the pull request out of the reviewer's "review requested" list.
04

Consequences

  • An issue_comment workflow runs with a write token even for comments on pull requests from forks. Any change to review-request.yaml must keep it from checking out or running pull request code, and from putting comment text into a shell command. AGENTS.md says so.
  • Every comment in the repository triggers the workflow, but the job's if skips it without starting a runner unless the comment is the author's /review on an open pull request.
05

Where it lives

  • .github/workflows/review-request.yaml
  • CONTRIBUTING.md (Pull requests, item 6)
  • site/contributing.html (#pull-requests)
  • AGENTS.md (Layout, workflows)
